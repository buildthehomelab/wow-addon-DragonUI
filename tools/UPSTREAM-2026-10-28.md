## Measured coverage and remaining unit-test gaps

`tools/measure_coverage.py` runs every `*_test.lua` suite with a Lua 5.1 line hook.
Its denominator includes every addon Lua file, including unexecuted files and
nested functions, from luac instruction source lines. It strips BOMs only in parser
input. It fails if any suite fails. The checked-in `coverage-baseline.json` is a
measurement snapshot, not a claim of full coverage or a merge coverage gate.

The local and isolated Linux worker runs agree: **5,382 / 151,336 executable lines
(3.56%) across 352 addon Lua files**, ten suites passed. Branch coverage remains
unmeasured. The broad denominator includes third-party libraries, locales and
large generated data tables. Full unit coverage is unfinished: most production
modules, upstream bank-sort throttling, spellbook catalog variants and compatibility
paths still need dedicated behavioral fixtures; the client checks below remain
necessary. UI scale lifecycle and Evermore's integration fixes have behavioral
regression cases against production code. This PR does not complete the fleet's
full-coverage objective and must not be described as fully regression-covered.

using Lua/luac 5.1, or supply `--lua` and `--luac` paths. Worker execution used only
public addon sources/test files in an isolated directory; it did not access realm
